## Context

先要区别三个层次：LLM SDK 返回 token、业务能在模型未结束时提交完整短句、TTS 在文本未全部输入前回传音频。现状有第一层的调用形式和整答后的 PCM 分帧，但缺第二层；Kokoro 当前 adapter 也没有第三层的模型级实现。

本变更交付必须先实现第二层和可打断的端到端流水线。云双向 TTS / 本地回调是减少单句内部首包等待的增强；不能等它们接入才开始改业务流，也不能把“完整答案生成后切文件”算本变更完成。

## Goals / Non-Goals

首个实质短句在 LLM 完成前可见可听；长答按自然语义连续说；所有阶段可撤销；私有指导始终约束输出。保留现有输入协议3、动态判停和直连校正，不训练 S2S，不强制迁移 RTC/Pipecat/LiveKit runtime，不为了增量语音扩大工具权限。

## Decisions

### D1. 共同 ResponseStream 替换草稿发布与整答电话分支

```text
最终用户表达 / 原题
  → Decision + GuidanceSnapshot
  → LLM 流 (正文与 tool call 控制分离)
  → 短句聚合器（私有可变 buffer）
  → 按 B 校验完整公开单元
  → 原子 commit Segment
        ├─ text delta → 同一 AI 气泡
        └─ TTS 队列 → PCM 帧 → 浏览器播放 → playout ack
  → LLM end + buffer flush + audio drain → 响应归档
```

Response 维护原题集合、reply_kind、output_generation、状态、committed_text、spoken_prefix、source revisions 和 segments。候选 token 仅服务端/授权调试可见，不直接向 Talker 广播“未校验预览”。文本可按已提交短句不断增加，不一定每个 token 都刷；这是可接受的公开流式单位。

分离 `generation_done`、`text_completed` 和 `audio_completed`；不能文本结束就假设音频已听完。整答音频下载文件在后台归档，不阻塞首声；撤回时归档同样不可读。`interrupted` 保留公开前缀，`withdrawn` 隐藏整 response。

### D2. 真正去掉模型流的聚合阻塞

CallReasoner.plan 只返回路由/依赖/工具需求，不再在 JSON 内生成完整答案；answer 提供 `AsyncIterator[ResponseEvent]`。VoiceAgent 的工具调用轮保持 assistant/tool 成对，但不再把无 tool_call 一轮全部缓存在 `chunks` 直到结束。

工具模型若支持正文和 tool_call 混合流：tool 参数、推理过程、role 标记永不进入公开短句；正文仅按明确 assistant content 通道解析。模型若可能先输出未确认事实再调用工具，采用两阶段路由控制：先短小决定工具/依据，再流正文；不发布工具前的猜测。通过 C 的合法 acknowledgement 填空隙，不能朗读原始 JSON 或链式思考。

工具配置和能力清单可缓存，不在每个普通问题的关键路径发现全部 MCP、读取全部技能和预加载无关文档。只有决定需要且符合 A 的只读配置时，才惰性初始化对应连接器；用户指定资料读取绑定当前题和来源，不扫描历史全部 URL。缺连接器按真实能力限制回应，不能让无关连接失败拖住常识回答。

固定快速模型用于通话默认正文，预算内至多一次首个公开段前的备用；文本模式可使用既有模型选择，但公开后也受相同“不 reset 已交付内容”约束。模型/SDK 不提供稳定可取消内容流则明确 capability 降级，不伪造 token 流。

英文约束在生成 prompt 与短句检查时处理；检测中文或私有指导泄漏时丢弃该私有候选并局部重写/停止，不在流已公开后整答翻译 reset。确需翻译的授权事实在进入正文前规范成英文依据，保留原始数值和限定，不能追加整答翻译调用到每题关键路径。

### D3. 语义短句，不逐字念、不按固定字符硬切

英文按自然完整句组织，不要求首句压缩为4–9词。过短完整开头可与下一句理由合并（当前聚合建议少于8词时暂存，合并单元不超过32词）；短整答结束后立即提交。首句没有合法边界时不强行切半个 ID、数字、小数、缩写、URL、专名、否定或条件句。

聚合器处理跨token标点和缩写；逗号和词数不单独触发分段。暂存完整不可分事实，不能把尚未出现的“not/except/unless”留到后段才修正前段事实。正文合成与音频发送分为有界并行阶段，使用跨段连续时钟及少量抗抖缓冲，避免每段增加一次合成空等；停止和版本失效覆盖两个阶段。

用户要朗读代码、长 URL 或表格时转口头概括 + 可见文本；不把 Markdown 标记或链接逐字合成。文字和语音意义一致，可剥离格式/替换可发音形式，但不得改变数字/单位/否定。任何只在屏幕展示的来源列表明确 skip_tts。

### D4. 合成策略与选型

统一 adapter 能力声明：

```text
supports_text_stream, supports_audio_stream, supports_cancel,
supports_word_timestamps, native_concurrency
open_context / send_text / finish / cancel / audio_events
```

P0 `KokoroClauseAdapter`：每个已提交短句立刻进入当前 `synthesize`，生成下一句与上一句播放重叠。它支持回答级增量，但当前 native 生成仍可能等单句 PCM 完成，能力标明 audio_stream=false；不可声称原生双向 TTS。先核验当前 Python binding 是否支持有效样本回调/取消；能用则转回调桥接有界队列，不能用则保留短句降级，不把 C++ 文档当已安装功能。

P1 可配置 `DoubaoBidirectionalTtsAdapter`：优先对接官方双向接口，把已验证短句持续送入同一有声上下文并消费 PCM；实施前核验当前版本/音色、flush、取消、时间戳和错误恢复，详见[调研](../../response-flow-research.md)。文本先经过同一约束检查，不能因云 API 支持 token 输入就绕过发布边界。凭证仅在后端，不复用 LLM key；无配置继续本地可用。

如果强需求离线原生双向模型，CosyVoice 是后续候选，不是 P0 必做依赖；先证明现有短句流水线收益，再根据实际硬件和英文效果决定，不为此启动大规模模型对比。

TTS 会话中固定音色/采样率/语速，句间只保留自然标点停顿，不每段插一大截静音。双向引擎可复用上下文保留韵律，但不能夹带私有 Wiki。不同 response 音频只能串行，不能混播；合成可有限预取。

### D5. 有界队列与 native 锁

每个响应最多预取约两段/约四秒的未播语音；客户端目标播放排程仍约 120ms，网络帧约 20–40ms。服务端私有文字 buffer 初始限制约 4096 字符；到界就暂停消费/请求短结尾，供应商持续灌入则取消并明确截断状态，不能无限内存或静默丢 token。文字无音频模式使用独立发布背压，不被不存在的 TTS 堵住。

全局 native TTS 单 worker 保持模型安全，有界任务队列按活跃有效输出调度；被取消任务离队。native 线程不可立即终止时继续持有锁直到退出，但网络控制、ASR 和下一轮 LLM 不等这把锁；新回应显示实际等待。段长上限降低旧任务占锁时间。不能声称 async task.cancel 已中止本地推理或创建第二个线程并发绕锁。

队列满时暂停上游，不抢占截断正在播放的完整句；显式用户打断除外。合成速率跟不上播放时，如实记录 underrun；优先简短结论，避免持续几分钟长读。不得用整答预合成重新引入首声等待。

### D6. 贯穿全阶段的取消

`output_generation` 表示当前可公开输出所有权，与输入 ASR turn revision、工具 job attempt 分开。语义确认插话、Hinter stop/封禁、手动撤回、模式切换、挂断会撤销相应 generation 或 response；只撤相关问题，保留独立待补。

取消广播至模型、路由/检查任务、工具、聚合器、TTS 上下文、服务器音频队列和浏览器 AudioBufferSource。确认中断控制优先，不排在音频大锁后。每次异步 await 返回都检查 owner / response状态 / segment版本，native 迟到也只能丢弃。

思考时确定有意义语音可转倾听，采集照常。播放时附和/有效插话规则沿用上一增量；不因文本流可见而关闭麦克风，也不等整段 audio_end 才能接受新请求。纯 stop 不创建应答声；候选降音和已确认取消分开。

### D7. 公开后故障不能整答重置

首段公开前可以在总预算内重试模型一次并清私有 buffer。首段公开后禁止 `reset=True` 擦掉已经可见/已说前缀，再让另一个模型从头读。保留 committed/spoken 前缀，标 partial_failed；可给明确简短失败或以新 response `continuation_of` 续答，输入包含实际已公开前缀且明确不重复。默认先安全结束，避免长备用链。

TTS 段失败时不重复已播段：文字可以继续完成，音频标 unavailable/partial；若切换备用 TTS，须在未播段边界，确认采样率与音色变化，不从响应头部重播。缺少精确词级对齐时，中途断网的当前句无法无重复精准续播，应提示可重播该句，不谎称精确恢复。

### D8. 播放确认、记忆与撤回

详见[协议](contracts.md)。服务端保存 text_committed 与 client_played 两个前缀。文本模式公开文本就是已展示上下文；电话上下文默认使用已播确认部分，另行标明已展示未播的文字，不把未听尾部写成已经说过。没有词级时间戳时只确认完整播放短句；中途一句标 `partial_unknown`，不能按字符串比例估算精确已说词。自动记忆不把模型结论提升为人工核实事实。

断线快照保留 response/segment/withdrawn，重连先拉取当前状态；不自动重播全部历史声音。客户端重复 ACK 幂等，旧 generation ACK 无权复活撤回内容。人手动重播只作用于仍公开且有音频的 response，不影响自动任务顺序。

### D9. 性能与最少验收

首个实质段 **必须先于 LLM end**，以服务端时间戳和实际播放记录证明；完整模型答复明显长于首句时才是有效样本，不能拿单句回答自证流式。拟定暖机短问实质音频 ≤3 秒，确认插话后停止旧声音目标 ≤200ms，网络/声卡实测另记；现有本地 TTS 可能达不到首声目标，须如实记录与后续 adapter 选型，不把目标写成已达成门槛。

十秒是前台得到结果/明确状态的共享边界，不是长答播放总长；开始实质流后，独立监控生成/音频空闲超时，不能让 stalled stream 永久占“思考”。首声、首个实质音频、合成 RTF、段间空隙、缓存深度、取消后迟到帧分别记录，复用日志即可。

## Migration

先建立 ResponseStream 事件与私有聚合器，接三种入口；再切公开提交、TTS 与新输出协议，一次切换单 session 所有权。历史草稿继续私有；历史完整音频可播放但不成为新回复关键路径。输入协议3不改，输出协议独立协商；旧页面收到升级错误需刷新，不允许同一活动响应混用旧/新帧。

旧的整答 check 不与新段级 check 永久串行叠加。新 publisher 接入后删除该分支的旧整答门禁，保留审计来源和撤回不变量；实施状态文档明确本地“回答级流式”和供应商“原生双向”各自完成情况。

## Verification

只需几个关键证据：长答案首句播放早于模型结束；工具正文不缓存整轮；中文候选不公开再整答翻译；思考/检查/合成/播放四处取消均无旧帧；Hint 途中更新；模型公开后失败不从头重播；断网/撤回后不恢复隐藏内容；三个入口普通题无需确认。优先复用现有测试与少量真实实听，不建立大型自动题库。
