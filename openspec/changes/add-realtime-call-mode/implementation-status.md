# 第一版实施状态

依据用户后续决定，本轮以功能落地为主，保留必要的角色隔离、输出前 Wiki 检查与中断控制，没有另建测试题库、审批系统或全量性能验收工程。

## 已实现

- [x] 保留审核聊天，新增开始通话、持续语音、静音、挂断、断线重连与资源释放。
- [x] AudioWorklet 持续 PCM → sherpa-onnx 在线识别/分轮 → Agent 拆分/分类/自动短答 → Wiki 检查 → Kokoro 分句/连续音频返回。
- [x] 开放新领域和实际数据查询等待提示；危险协助拒绝；中英文离线词表作为分类信号，策略可编辑。
- [x] Hinter 监管时间线、风险待办、提示后回答、立即纠正、仅后续生效、别回答、暂停/恢复；可启用提醒声音。
- [x] 提示原文持久化、私有 Wiki 投影、可选跨对话约束；最终候选按最新约束复核。
- [x] 输入/输出取消使用 call epoch，停止后丢弃旧音频；已播完和中断状态分开。
- [x] 现有 session 的 Whisper 复用、Intake 锁外推理、控制事件唤醒、DeepSeek 非思考调用。
- [x] 新 Hint 异步回查提交时最近5题，封禁命中后自动撤回并隐藏；Hinter 可逐条手动撤回全部历史 AI 回复，旧音频链接失效，Wiki 对应原文持久隐藏。

## 验证记录

- 前端 TypeScript/Vite 生产构建通过，后端 Ruff 通过，26项测试通过（含2项追溯撤回回归检查）；未新增大规模测试工程。
- 实际模型区分账户身份封禁与普通回答长度提示；撤回检查覆盖窗口冻结、检查期间新回答、旧音频链接及 Wiki 重启后不恢复原文。
- 独立合成英文音频以连续 PCM 输入：识别 “What is the capital city of France”，自动答复 “The capital city of France is Paris.”，返回55个语音帧。
- 浏览器 Hinter 处理实际 DAU 查询：问题等待提示，输入已核实数字后生成一句英文语音；Talker 快照不含私有提示 canary。
- 播放中 Hinter 叫停：本地控制链路约34ms收到停播事件，事件之后旧音频帧为0；暂停/恢复撤销暂停约束。此数字不是跨网络/扬声器端P95。
- 同一音频非思考调用前后“输入开始至首音收到”约12.3s→7.8s，包含说话时间；没有将其冒充语音末尾至实际可听的TTFA目标。

## 与原提案的范围差异

1. 第一版选择规格允许的持续 PCM WebSocket 路径，没有安装 Pipecat/WebRTC，避免引入新的媒体服务。接口为 `/api/v1/ws/sessions/{session}/calls/{call}`，首条消息传身份，后续上行16kHz PCM、下行带epoch的24kHz PCM。
2. 使用 sherpa 自带在线端点检测，不额外叠加 Silero。实际小型ASR识别不佳，换为 `en-2023-06-26`。
3. 数据通过 Hinter 提供已核实内容，call 完全不注册查询/bash/MCP工具，因此没有再建设 ToolGrant 系统。
4. 使用 SQLite session 持久约束和可恢复 Markdown 投影，未引入独立约束数据库/outbox平台。已保留当前和历史call记录；生产事务、精确词级播放对齐等后续按需要增强。
5. 未跑100轮性能基准、10分钟压力/全浏览器矩阵、HTTPS/TURN/WebRTC验收；原 tasks 中相关条目保持未勾选，不将其描述为通过。
