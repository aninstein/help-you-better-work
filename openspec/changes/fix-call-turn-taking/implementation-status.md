# 实施记录

2026-10-22，按用户“规格没有问题，直接落实”实施；主链路已接入，保留原消息/录音模式、Hint/Wiki与撤回能力。新通话使用turn_protocol=2，更新本地服务后需刷新并重新拨打。

## 已实现

- TurnAssembler按音频采样时间累积完整原话，3000ms有效静音才封存；ASR内部endpoint不创建消息，最终只提交一条Talker输入。
- 服务端Silero ONNX独立状态识别人声；浏览器RMS只显示音量。约100ms的音节间隙缓冲避免持续人声计时被词间间隙清零。
- 有效插话走独立的epoch取消/停播路径，和三秒轮次结束、ASR/校正分离；停止/挂断/撤回不等待校正。
- 完整原声通过预热small.en CPU/int8二次识别，停顿中预启动，封存后额外等待有上限；不反复上传录音，不引入PyTorch。
- TranscriptRefiner固定模型客户端直连，一次非思考调用，无Wiki、工具、主Agent或模型池逐级重试。当前默认优先已有Flash类低延迟配置，可用CALL_TRANSCRIPT_MODEL独立指定。
- 校正自然大小写和标点，保护数字/ID/单位/日期/否定。冲突或无依据改动进入澄清；失败保留原话并明确降级。
- 冻结快照与输入revision使校正期间续说合并、旧结果作废；原生推理期间断开也不会复用尚未结束的可变识别状态。
- 临时字幕/等待/整理状态复用紧凑输入区；原始识别与耗时只在Hinter消息详情按需展开。新增provenance字段复用角色和撤回投影。

## 验证

- 后端现有测试最后一次完整运行：35项通过；本轮新增4项聚合回归，覆盖短停顿、单条提交、输入上限、校正期间续说/Hint、旧结果晚到、关键槽位与直连无fallback。最后冻结快照调整后另运行6项分轮/撤回检查通过。
- TypeScript/Vite生产构建、Ruff与git diff检查通过；两个OpenSpec变更严格校验通过。
- 在独立SQLite/Wiki目录运行真实Silero、sherpa、small.en、当前配置的LLM和Kokoro：两段合成英语中间停顿2秒，最终只生成一个用户气泡和一个问题。
- 同一回放中online raw为 `HE EXPLAIN THE MEANING OF DI A U AND A P EY LIMITS`，最终为 `Could you explain the meaning of DAU and API limits?`；原声与各阶段文本保留关联。
- 该次采样记录静音3008ms，整段识别1079ms（与停顿期重叠）、直连校正1277ms；这些是单次合成音频结果，不是真人准确率统计或P95。
- 随后的单帧噪声脉冲没有取消输出；连续合成语音插话在800ms兜底条件下确认，中断事件之后旧epoch发送帧为0。验证的是本地服务取消链路，没有声称真实扬声器尾音为0。
- 浏览器确认完整英文气泡、默认折叠识别详情、校正状态/耗时，以及人工撤回后内容隐藏、原始用户问题仍可查看。
- 旧录音上传带明确转录→pending_review保持不自动回答；原始音频播放接口200。校正期间Hint原文不进入校正metadata；既有撤回、旧音频410与Wiki不恢复原文检查保持通过。

## 实施调整与边界

1. 校正最初1500ms预算在当前服务配置中频繁超时；少量独立服务调用测得约1～4秒（含一次3.21秒与3.83秒），故默认CALL_TRANSCRIPT_TIMEOUT_MS调整为4500，可配置回1500。没有增加重试或模型池；超时仍保留可靠原话/澄清。完整ASR封存后额外等待保持1500ms。
2. 保留既有PCM/WebSocket，不引入整套Pipecat/LiveKit或额外Agent编排平台。Silero直接用现有ONNX运行环境，每通话独立h/c状态。
3. 已确认取消的输出不做自动断点续播；假噪声候选在确认之前不取消。VAD不是回声消除，建议耳机；没有做真实嘈杂环境、全部口音、跨浏览器长通话或P95基准。
4. 当前单进程更新需重拨，旧未提交输入不跨重启复活；旧历史消息不批量重写。原始ASR与LLM均可能犯错，不能将格式校正当成听力准确率保证。
