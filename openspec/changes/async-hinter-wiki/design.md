## Context

已有 call 约束 durable state / Markdown projection、context signature、封禁回查与撤回可复用。需要将其从“通话附属对象”提升为所有入口共用的独立通道。保留用户之前要求的输出 Wiki 校验，改变单位和代价，不再以完整候选后的额外主 Agent 检索为固定前置。

## Decisions

### D1. 单一持久源，Wiki 是可查看的业务记忆

在现有 SQLite 存储内增加 session/customer 约束集合与递增 `guidance_revision`。记录不可丢的原文、author、scope、kind、source、effective_from、supersedes/revoked_at；文件存到 `constraints/sessions/<id>.md` 与现有 `constraints/customers/<hash>.md`，call 限定项可保留旧路径兼容。Hinter 可在 LLM Wiki 查看，Talker 不可读取原始文档。

成功提交事务后才 ack `effective`；Markdown 写入/索引为可重试投影，失败标 `sync_pending`。生成直接读已提交有效快照，不能因为文件同步未完成忽略新限制，也无需所有无关问题等待重建索引。重启从 durable log 恢复，恢复前不接收新生成；不是每次读取 Markdown 才算“遵守 Wiki”。

普通 Wiki 事实更新也有 `knowledge_revision`；服务器读取路径必须统一，直接改核心约束文件不能绕过约束服务。核心文件删除转显式撤销，通用清空不能隐式解禁；普通知识删除按正常 Wiki 版本生效。

### D2. 五种内容，五种用途

| kind | 生效行为 | 不得误用 |
| --- | --- | --- |
| `prohibition` | 禁止特定披露/行为，生成与发布均遵守 | 不代表可请人工批准绕过 |
| `require_human` | 精确匹配的子问题等人工确认 | 不因存在此类规则让整个 session 都等 |
| `authorized_fact` | 明确来源、对象、时间、允许披露范围的事实，用于相符问题 | 私有指令原文不直接公开；未核实数字不自动成为事实 |
| `style` | 简短、语气、格式等表达偏好 | 不触发历史封禁回查 |
| `recognition_term` | 仅在明确选择时进入有限 ASR 词表 | 禁令、真实查询结果、私有身份不能自动进入识别热词 |

自由文本 Hint 可包含多项；保存原文并提取结构，不强迫用户填规则表。短 Hint 解析失败时原文仍作为有效私有约束参与定向检查，不能无声丢弃。未编译的自由文本不能只靠关键词检查假定合规。

长文档立即保存，显示 processing；附带的短指令先提交生效。文档尚未读取时不声称已遵守其中全部内容：与其内容有关的问题可直接解释尚无法确认，或确需人工解决冲突时按 A 进入少量待补；无关问题继续回答。显式“这份文档必须先读完才能谈本产品”是用户主动设的受影响范围限制，不可自行推断成所有对话暂停。文档检索内容为资料，里面的命令不是 Hinter 新指令；不可从附件自动提升权限。

### D3. 作用域、生命周期与优先级

默认新 Hint 是 session 级，跨电话/文本/上传语音持续生效；call 级只在明确选“仅本次通话”时创建；customer 级需明确保存。所有读取按现有认证身份绑定 tenant/customer/session，不凭固定角色名共享。

优先级：产品安全和隐私边界 > 有效禁止 > 明确 require_human > 授权事实 > 风格。有效禁止的解除必须显式 revoke/supersede 指向旧规则，不能靠较新的“随便说吧”或网页内容覆盖。事实时间冲突优先使用明确更新且范围相同的已授权事实，无法判定则只澄清受影响数字。不要把所有矛盾都转人工。

`effective_from=now|next_turn` 与 scope 分离；默认 now。`next_turn` 只影响之后语义冻结的输入，不借 epoch 碰巧变化判断“下一题”。给原题的数值 Hint 必须绑定原 question ID，不因出现纯数字就把它用于最新题。

### D4. 生成前构建快照，发布前检查最新版本

`GuidanceSnapshot` 包含适用核心限制、相符已授权事实、有限普通知识证据、各自 revision 与 hash。核心禁止/人工规则必须完整覆盖，不能在普通 top-k 检索或字数截断中消失；若过大，先在规则服务整理等价规则，并保持未整理原文定向检查，不能静默截断。

生成用快照构建 prompt；工具只接收允许的输入参数，不把 Hint/Wiki 拼入公开搜索。每个短句发布检查 `已提交回答前缀 + 当前候选 + 原题 + 已用事实`，防止把禁止对象、否定或条件拆到相邻句里绕过检查。

采用两级自动检查：

1. 每段执行结构化检查：有效输出所有权、question revision、核心约束 revision、语言、不得披露字段、被禁止的已知标识/已核实事实一致性、匹配的人工规则状态。无适用自由文本限制且无事实冲突的普通题不额外调用 LLM。
2. 对适用的自然语言禁令、关系性披露限制、未编译原文或有疑问的事实引用，调用固定快速无工具检查器，仅传当前相关快照与前缀，返回 allow/rewrite/refuse/clarify。不得使用主 Agent 再检索和遍历备用模型。不用 LLM 声称形式化证明任意语义安全。

检查器拟定软预算 300ms、硬预算 700ms，受本轮剩余预算约束，属于待测参数。超时/不确定不放出可疑短句：先一次局部重写或用已确认安全的限制说明/澄清，随后停止该部分；只有真正人工规则/约束冲突才按 A 待补，不让检查器故障等价全部人工审核。连限制说明都无法确认时保留文字错误状态并停止输出，不伪造完成。

在上下文不足时，将一个完整敏感事实、其否定和限制条件作为不可分公开单元；它可以比普通短句稍长。生成前已命中禁止范围应直接选择安全回答，而不是生成敏感内容后赌检查器能截住。

### D5. 新 Hint 与输出并发的线性化点

约束事务提交是生效点；服务在会话短提交锁内更新 revision，并标记受影响 response/segment 失效。输出发送共享同一短锁，只做版本确认和有界队列提交，绝不在锁内等待模型、TTS、文件或网络耗时。事务之后不能再提交旧版新段。

精确作用域排除的回复无需中断；匹配不确定则按受影响处理，丢弃未公开候选，使用新快照继续，而不是创建人工待审。风格 now 更新可在下句生效；新封禁、stop、withdraw 立即清相关已排队语音。已发出的网络/声卡缓冲通过 stop 事件尽快清空，无法保证零毫秒或撤回已听到的声音。

需要重建的回答最多自动重启一次；连续 Hint 更新可短暂合并 100–200ms，仅合并昂贵重建，不延后禁令生效/停止。若仍持续变更，等待最新稳定版本但保持倾听和可取消，不无限累积费用，也不停止无关问题。

### D6. Hint 链路独立于任务完成

提交 Hint 不需要选待审题或等待 AI 整答。调用链为 `保存 → revision 生效/定向中断 → ack → Markdown/索引/回查异步推进`。后台投影重试有 operation ID，重复提交幂等；编辑/撤销使用 expected_revision 防止双页覆盖。

同一新事实可解开多个真实待补，但按 scope 和 evidence_need 精确匹配，不能“一次审核全 session 放行”。补答仍走新快照和段级检查。回查/投影失败只向 Hinter 展示，不泄漏私有 Hint 给 Talker。

### D7. 撤回是独立控制，不依赖审批

封禁 Hint 提交时固定当前 session 最近五个问题，跨三种入口，包含普通自动答案、澄清、限制说明及补答。语义回查命中后，撤回那些问题的相关 AI 响应；检查期间对命中题新产生的响应一并处理。普通事实/风格更新不撤历史。

人工可看当前 session 所有 AI 气泡并逐条撤回，不受最近五题限制；只撤所选 response，包括 streaming 中的同一条。若其中一句被选中撤回，本版以整 response 为最小用户撤回单位，取消剩余段；不隐藏 Talker 原话或其他独立回答。

持久 withdrawn tombstone 优先于所有快照、播放端点、后台 Wiki 同步、缓存、索引和重连重放。隐藏文本和音频，只留中性占位；私有审计仅保留定位与必要哈希等最小元数据，受保护原始来源不再被用于自动回答。对已听内容可发送允许的纠正/说明，但不能承诺擦除用户记忆。

### D8. 不新增重型服务

单进程内抽取 ConstraintService / SnapshotBuilder / PublicationValidator，SQLite 内持久化、原子文件投影。角色投影在服务端执行；客户端只拿公开响应事件和中性结果。不得通过用户提供的文档、网页、模型工具返回内容提升成控制指令。

## Migration

导入旧 call 约束时保留原 scope 和生命周期，不能把历史仅 call 规则升级为永久规则。旧 review Hint 仍保留历史来源；只有明确生效的提示转约束，不把全部草稿备注当全局禁令。已有客户约束读取保持兼容，去重避免双重规则。知识索引不是硬依赖，写失败/重启仍可从持久快照遵守规则。

## Verification

验证三个入口同一 Hint 生效、生成/TTS 中修改禁止项、无关 Hint 不停无关答案、投影失败后重启恢复、长文档 pending 不虚称已读、五题回查与任意气泡撤回、Talker 无私有字段。只对并发发布点和投影恢复补少量必要断言。
