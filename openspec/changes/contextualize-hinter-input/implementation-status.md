# 实施状态

已接入现有 planner、Guidance 持久化与 Wiki 投影、统一的消息/通话生成链路。Hinter 问题卡、提示输入区和通话监管卡复用 AssistanceBrief，展示私有补充任务。普通问题不新增等待或模型调用。

## 实际验证
使用隔离数据目录创建待补问题，通过真实配置的生成模型验证：
- TikTok DAU 原题，显式为该题补充 `200`，实际输出 `TikTok's DAU is 200.`
- AICO 提效原题，只有这一题待补时发送 `50%`，实际输出 `AICO improves efficiency by 50%.`

两例均保存原始发言、提取题目、补充任务和 Hint 原文的关联；没有自动添加 million/billion。多题未指定目标时，裸数值返回选择题目的提示，没有作为全局事实写入。Talker 快照不包含私有补充任务或 Guidance。

另验证：通话正在处理其他话题时，裸数值仍关联唯一待补的原题；输入期间题目被处理后，不会将数值自动转给另一题；禁止事项不会因入口为补答被误标为事实。

浏览器已验证问题卡与输入区展示人工补充任务，以及选题后只填 `200` 的英文补答。

前端 TypeScript / Vite 构建通过；修改的后端模块 Ruff 检查通过；新 OpenSpec 严格校验通过。只做与本改动相关的功能验证，未扩展历史审核测试或新增审批门禁。
