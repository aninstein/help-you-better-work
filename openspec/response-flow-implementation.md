# 自然交流与异步 Hint：实施记录

2026-10-22。按 B 基础 → A → D＋B 输出检查 → C 完成核心链路。用户随后明确优先功能，不适配历史审核测试、不扩建测试题库或额外门禁。

## 已接入的功能

- 三个入口默认自动回答。问题记录不等于待审核；常识短问不必额外调用模型做一次“允许回答”路由。哲学、新话题、轻微脏话、一般歧义和失败不默认转人工。
- 问题保留独立状态、来源与依赖；真实内部数据缺失时先明确说明，再等待已核实依据。危险协助由 AI 拒绝；明确禁止项不反复请人工解禁。
- Hinter 有独立提示通道，不选问题也能发送。提示存入 SQLite 追加日志并异步投影私有 Wiki；可修改、撤销、选择客户范围。普通风格默认影响后续轮次，避免打断当前语音；显式纠正和禁令立即作用。
- 新依据会自动重判原有待补问题，能回答就补答；不要求再点击一遍审批。长文可作为参考资料保存，本地分块选择相关内容，processing 不阻塞无关问题。
- 生成中的完整短句立即公开并合成，后续生成与合成/播放重叠。文本、上传语音和电话共用 ResponseService；消息回复订阅声音不请求麦克风。
- 电话直接答案本身就是回应；慢生成可以给一次简短回应，公开查询/文档读取先回应再启动。后台 IO 不占声音锁；有限进度按真实状态触发，不逐题循环“收到”。
- 输入仍为持续 PCM 协议3；输出为带 response/generation/segment/frame 身份的协议4。StreamPlayer 共用于电话与消息，按实际播放确认段落；重连不自动重播历史声音。
- 停止、有效插话、Hint 变更、撤回、挂断和模式切换贯穿生成/合成/队列/播放。公开后失败不重置全文；未播尾部不记成已说。最近五题封禁回查与任意历史气泡手动撤回保留，撤回快照也隐藏分段原文。
- 新模式不依赖旧 ai_mode、review ID 或草稿确认。旧草稿继续私有，旧 held/expired 标为历史未处理，不批量发布或朗读。

## 主要实现

- `backend/app/application/guidance.py`：跨入口持久 Hint、作用域、快照与资料索引。
- `backend/app/application/responses.py`：逐题路由、自动回复、后台工具、短句发布、合成与交付。
- `backend/app/application/segments.py`：句子及可独立朗读从句聚合。
- `backend/app/agent/call_reasoner.py`：轻路由、直接正文流与适用禁令检查。
- `frontend/src/lib/streamPlayer.ts`、`hooks/useReplyAudio.ts`：统一 PCM 播放与消息音频订阅。
- `frontend/src/components/GuidanceList.tsx`：消息/电话共用提示修订与撤销。

普通事实、风格与公开检索不再固定加一次模型审查；明确禁令/人工规则和未编译的自由文本限制才使用定向快速检查。该检查无工具、无Wiki二次检索、无模型池长重试；当前有界等待为1.5秒，未采用设计稿700ms的激进值。保留的是用户明确要求的限制，不恢复例行人工审核。

## 实际运行及边界

前端 TypeScript/Vite 构建、后端编译可完成。真实已配置模型与本地 Kokoro 已跑通自动文本问题、分段正文和 PCM 返回。一次冷合成 API 解释样本约3.8秒首段发送；这是服务端发送口径，未含真实麦克风识别及扬声器播放，不代表暖机P95或豆包同等体验。短答模型可能在首句合成完成前就已结束生成，不能据此宣称原生S2S；代码没有等待完整答案才开始合成。

本地 Kokoro 当前是回答级短句流水线，单句 native generate 仍需完成才返回PCM；取消后保持模型锁直到原生推理结束，采集和控制不等该线程。已核对安装版 Python 的生成回调接口，但未将未经实听确认的原生中止语义接入。短回应在启动后预热并缓存。

豆包云端原生双向 TTS 为设计中的可选P1，本轮未接入/启用，未新增云语音凭证或上传原声。当前不接真实业务数据库，不包含PSTN、词级精确半句对齐或全环境声学验证。

已有少量新流程检查在用户明确停止测试工作前执行过；本轮之后以功能、构建和实际运行核验为主。历史逐题审核测试未整体适配，不以其通过作为功能门槛，也不声称全部旧测试通过。

## 重复澄清问题修复

实际通话记录暴露了三处问题：判停的 semantic_uncertain 被当成内容不清楚；needs_clarification 绕过正常理解直接播放同一句固定文案；整理器只读取 completed 状态，漏掉已变为 intake_complete 的历史用户消息。现已分离判停与内容判断，修复历史读取，二遍繁忙时增加最多750ms可取消等待，缺失二遍只标降级。关键数字/ID/否定冲突仍保留局部确认。

正常回答改用真实 Human/AI 消息角色，避免复述用户的第一人称或旧回复。具体澄清由同一次轻路由生成，泛化、重复或不可用结果会按实际不清楚的槽位收窄，不再额外启动一次正文生成。历史录音重新识别确认订房意图清楚；原姓名/ID录音二遍可恢复更多内容，但不把重识别值视为已核实事实。独立存储中的实际模型回放已验证订房正常追问入住时间、模糊词局部追问，以及关键ID冲突仍确认；未改写原会话消息，也未重跑旧审核测试。

## 连贯语音与个人助手人格

原audio_worker直到上一句发送结束才开始合成下一句，已拆为有界并行合成/发送阶段，下一句可提前准备。首个实质单元独占首答截止，预合成续句使用自己的合成等待时限，避免首句已就绪却因发送尚未更新标记而误取消续句。连续发送时钟保留120ms发送提前量，客户端初始缓冲约80ms；正常回复切换不再stop尚未播完的末尾，明确取消仍清所有声音。SentenceBuffer不再按逗号切分，短开头可与下一完整句合并；未等待完整长答，不新增云TTS依赖。

三入口及旧草稿/润色共用`agent/prompts/persona.md`：温和、好奇、务实，有明确的推荐倾向，保持助手与用户偏好的主体归属。Wiki整理明确不得把AI的推荐记录成用户的最爱。拆题/转写继续走轻量固定路由，正式对话默认直连用户配置的主模型（可用CALL_RESPONSE_MODEL覆盖），不再用拆题模型承载全部人格输出，也未引入主Agent的额外检索或工具流程。

实际模型验证中，用户记忆为《教父》时，问助手偏好得到《降临》及理由，问用户偏好才得到《教父》；无问号的项目近况也正常交流。实际Kokoro三句合成/发送验证中，后句合成与前句播放重叠，两个服务端边界未出现合成空等；不据此宣称所有设备零间隙或原生S2S。预合成期间停止的定向检查确认没有继续发送旧帧。前端构建与后端编译/静态检查完成，未运行历史审核测试矩阵。
