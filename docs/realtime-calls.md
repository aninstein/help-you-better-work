# 实时通话

这是与自动消息回复共用回答链路的浏览器通话。点击一次接通后，AudioWorklet 持续发送 16kHz PCM，服务端在线识别和自然分轮；AI 的 24kHz 音频也分帧持续返回，不走录音上传接口。不包含真实手机号码/PSTN。

## 使用

1. `./scripts/build.sh` 安装依赖并下载本地模型，`./scripts/start.sh` 启动。已安装项目只准备模型可运行 `backend/.venv/bin/python scripts/prepare-voice.py`。
2. Talker 输入区顶部的文字、语音消息、通话入口统一为图标按钮；点击文字和麦克风图标旁的电话图标开始通话，允许麦克风后直接用英文问话。点击后默认展开覆盖聊天区域的通话界面，白色声纹圆环在倾听时随音量振动，思考时像心跳一样缩放；底部可静音或挂断。右上“缩小”或Esc可回到聊天，原输入区保留动态音频线，点击后重新展开。两种形态切换不重建音频连接。静音只关闭输入；挂断释放麦克风并恢复原消息输入。建议戴耳机减少外放回声。
3. 打开同一 session 的 Hinter 页。左侧持续显示转写和已校验的英文答复，右侧显示需要提示的例外问题。可开启提醒声音，不需要逐题确认。
4. 提示输入支持简短中文、数字和背景长文。默认“纠正并重答”立即中止当前回答；“仅后续生效”从下一轮使用；“别回答”停止当前问题；“暂停自动回答”后需明确恢复。
5. 提示默认在当前会话内跨文字、语音消息与电话生效，勾选“跨对话保留”则写入客户级核心约束。所有提示原文保存在 Hinter 私有 Wiki 的 `constraints/`，Talker 不收到私有提示或内部检查结果。

封禁原则还会自动回查 **Hint 提交时最近5个问题**，语义命中的已发回答直接撤回，界面显示“已撤回 · 内容已隐藏”。普通事实补充、数字纠正或“只说两句”等格式要求不会触发历史撤回。回查是异步的，Hinter 可以看到进度和结果，失败时可重试。

Hinter 可以浏览当前会话的全部 AI 已发回复，每个气泡都有“撤回消息”按钮。人工撤回不受最近5题限制，审核聊天、实时通话和通话结束后的历史消息均可操作；点击只撤回选中的那条回复，同一问题的其他回复不受影响。未发送的草稿沿用取消操作。

撤回会同步移除公开原文、复制/播放入口，拦截旧音频链接，并清理 Wiki 中对应的对话原文；刷新、重连或后台旧 Wiki 同步均不会把它恢复。已听到的声音和用户已复制到外部的内容无法撤回。内部保留撤回前记录供排查，但不通过聊天快照重新下发原文。

麦克风需要 localhost 或 HTTPS。语音连接丢失时停止旧输出并尝试重新接通，超过约10秒结束，需要重拨；重连不会重播旧语音。另一标签页不能抢占活动媒体连接。

如果文字回复正常但听不到 AI 声音，升级后先刷新 Talker 页再重拨：旧页面的 PCM 播放器不认识输出协议4。接通请求现在声明 `output_protocol: 4`，旧页面会收到明确的刷新提示；入口 HTML 不缓存，采集 worklet 每次重新校验。输入协议2的兼容与输出播放器版本是两回事。判断声音是否真正播放应查看 `playout.started` 和分段 `playout.ack`，不能只看后端的 `sent`。

## 停顿、插话与英文转写

接通后的初始状态为倾听，持续收音、实时转文字；本段确认结束才进入思考。思考期间识别到新的有效文字即取消当前思考、返回倾听，一个单词的补充也有效，无需等完整句或再次停顿。单纯声音而无有效文字不会确认业务中断。被取消的当前候选不会迟到播出，独立人工补答仍保留。

通话有“倾听中 / 思考中”两种活动状态，AI 播放时麦克风仍持续工作。新客户端使用协议3，Silero + Smart Turn v3.2 CPU ONNX结合字幕完整性判断交接，清楚完整短问不必等满三秒；未完的连接词、号码、ID或自我纠正继续等待，约六秒仍不完整则只澄清。明确说“Wait, let me think”保持倾听。模型推理最多200ms、每次停顿最多四次，使用当前表达末尾八秒及真实停顿，完整发言不被八秒窗口截断。续说、静音、缺帧、断线和挂断会使旧预测失效。模型不可用时原位说明约三秒静音回退，协议2旧客户端仍可使用。

插话单独判断：讲解中的yeah/uh-huh附和不取消输出，也不创建问题；期待确认时的yes/no仍有效。短stop/wait、纠正和新请求可确认中断。只有时长没有意图不会自动取消。尚不确定时先降低对应回复的音量，最多500ms自动恢复；确认后推进epoch并清旧播放，迟到恢复不能复活旧回复。Hinter停止、封禁、撤回和挂断继续立即执行。普通单通道VAD没有分离旁人的能力，建议近场单说话人、耳机环境使用。

在线 sherpa 只更新一个字幕槽，稳定前缀与可修订尾部分开传递；完整音频使用 faster-whisper small.en 识别。正式输入随后一律经过共享主模型的 TranscriptRefiner 做语义清理，包括识别质量较高的语音及文本输入；同一消息只处理一次。清理提示词位于 `backend/app/agent/prompts/transcript_refinement.md`，主模型等待上限至少 12000ms，不调用工具或备用模型。移除口头填充、重复、无意义的重新起句，结合声学证据修正明显用词错误，保留所有有效诉求、限制和上下文；保留原始识别、有效文本、删除片段、缺失信息和实际模型路径，超时降级不标为已校正。

数字、ID、日期、单位和语义否定有独立校验，不能因清理而改变。识别冲突仍需澄清；能独立对应且不含关键槽位的明确问句仍可先答。仅有口头噪声时不产生问答。对 “NO NO MURM ... WHAT'S THE WAITER IN SOME HA”，移除前缀并识别天气意图：若完整音频确认 Shanghai，则查询上海天气；城市仍不明确时只问城市，不追问 MURM 的含义。Hinter 可在消息详情查看原始/最终识别和校正路径。

判停置信度与内容是否清楚分开处理：完整订房等陈述请求可以正常进入对话，不因六秒等待到点而强制澄清。二遍识别暂时繁忙会短暂、可取消地等待；仍不可用时保留降级标记，不据此否定整个意图。整理器可读取当前通话最近两条有效用户消息；回答模型使用真正的用户/AI消息角色。具体澄清问题由主模型同时生成，不再额外生成一遍泛化追问；缺少可用结果时按实际姓名、ID或不清楚的片段追问，并参考已问过的内容改变方式。

Hinter通话栏的“识别术语”默认折叠，仅用于明确授权给识别器的产品名/缩写，最多50项、1000字符，下一段发言起生效。当前保持sherpa greedy解码以免新增在线CPU成本，已验证词表通过faster-whisper hotwords用于二遍识别。业务Hint/Wiki不会自动进入词表或改写原话。

完整语音识别可在停顿中预启动并复用，冻结后默认最多等2500ms；按需校正和后续拆题、最新Wiki检查、首段合成都共享冻结起点的十秒预算。清楚的语义交接不额外补等三秒。普通问题先答，人工题独立保留、后续补答，播放排队和人工等待另列。超过预算保留问题并继续倾听，不发布迟到候选。单轮上限60秒，超限明确请求分段重说。

采集记录真实getSettings和AudioContext采样率，申请浏览器AEC/降噪/AGC；不支持AEC时原位提示。非16k使用63tap/128phase抗混叠重采样。协议3的seq/sample_start/sample_count检测缺失、重复或格式错误；受损发言被取消并提示重说，后续残片隔离到三秒有效静音，不把断流或补零当成判停。控制事件不等待端点模型推理。

## 实际实现

- **媒体**：同源 PCM WebSocket + AudioWorklet。第一版采用已设计的持续 PCM 路径，直接复用 FastAPI，无需新增 Pipecat/房间服务。没有把上传分片伪装成流；WebRTC 可在后续替换传输 adapter。
- **英文识别与分轮**：sherpa-onnx 1.13.8、Zipformer `en-2023-06-26` int8用于在线字幕；Silero ONNX状态按通话独立，TurnAssembler保留完整表达，TurnController决定自然交接。ASR内部0.65秒/18秒分片不会创建消息。完整音频使用faster-whisper small.en CPU/int8二次识别，模型预热复用，Smart Turn固定revision与SHA256，官方Whisper特征提取器处理左侧补零后归一化。
- **英文语音**：本地 Kokoro int8，以自然完整句组织，过短开头可与解释合并，不再按逗号或强制短首句切分。合成与发送为有界并行阶段，播放当前句时预合成后句；续句不误用首答截止。40ms PCM帧使用输出协议4并携带段号，共用跨段时钟及少量抗抖缓冲，正常相邻回复保留句尾。消息和电话共用StreamPlayer并确认已播段；单个语音单元的native生成仍需完成后才返回PCM。
- **Agent**：三入口共用`prompts/persona.md`中的专业个人助手人格，能直接表达自己的推荐观点；用户偏好与助手人格分别归属。所有 LLM 阶段统一使用配置的主模型，不使用单独小模型或跨模型降级；常识短问可直达正文流，多问才拆题，不增加主Agent工具检索过程。先装配最新适用Wiki，只有明确禁令或自由文本限制才加定向短检查，不再每题总审。旧草稿保持私有。
- **公开查询与资料**：先说简短回应，再启动受控查询；后台IO不占声音锁，结果按原题回来。原话公开问题可联网，用户明确提供的文档可按只读方式读取；私有Hint/Wiki不进入公开搜索，不查询真实数据库。失败明确说明，不自动转人工。
- **策略**：普通话题、人生意义、歧义和处理失败不默认挂起。仅明确人工规则、实际缺少人工依据和约束冲突待补；禁令直接遵守，危险协助安全拒绝。
- **记忆与提示**：Hinter独立提交，SQLite先持久生效、Markdown异步投影。支持作用域、修订和撤销，普通风格默认下轮生效。新依据可自动解开相关待补并补答，无需逐题审核。
- **旧 session 提速**：Whisper 实例复用，Intake 推理移出 session 锁，控制事件更新可直接唤醒推送；DeepSeek/Ark 使用非思考调用，减少不必要的思考等待。

## 延迟与边界

实际音频验证已覆盖持续输入、识别、自动回答、Wiki检查与PCM返回；浏览器 Hinter 提示后回答、私有信息隔离与中断链路已验证。没有开展100轮基准或全浏览器矩阵，也没有宣称达到规格中的P95目标。

历史单条相同音频验证中，非思考调用使“开始输入到收到首音”由约12秒降至约8秒，该数字包含说话时间，不能当作用户说完后的首音延迟。当前十秒是处理截止机制，不能保证外部模型每次都成功，更不等于网络和设备可听时延保证。最近准备耗时单列排队播放等待；生成中的完整短句按适用约束检查后即播放，超时说明失败并继续倾听，不靠占位语音宣称实质首答达标。

Hinter 的暂停和短提示没有另加多轮审批。通话监管仅保留少量待补问题，可补充已核实信息或确认明确的人工规则。真实数据缺失不能仅点确认就视为已经查到。没有已核实的业务数据时，AI 说明无法确认，不猜测或自行查询。按提示回答的数据问题仍需人工提供已核实数据或说明。暂停或断线时保留待处理状态，恢复后重试。通话不自动连接真实数据库；跨存储的生产事务、真实手机号、WebRTC、精确词级已播对齐与大规模性能验收留待需要时扩展。

默认模型目录 `backend/data/models/voice`；可用 `DUET_VOICE_MODELS` 指定。`CALL_TURN_END_SILENCE_MS` 调整旧协议固定静音阈值；`CALL_END_SILENCE`仅调整ASR内部分片。`CALL_TRANSCRIPT_TIMEOUT_MS`调整主模型整理等待上限（至少12秒），`CALL_FINAL_ASR_MODEL`指定完整轮次英文模型（修改后需重新准备模型）。`DUET_PREPARE_VOICE=0` 可跳过本地构建的模型下载。Docker首次启动将模型下载到持久数据卷。ASR/TTS下载出处、SHA256与随附说明、Silero来源及许可链接保留在模型目录；完整英文模型来源为SYSTRAN/faster-whisper，词表归属见 `backend/app/agent/lexicons/manifest.json`。

本轮自然语音实施及回放数据见 [实施记录](../openspec/changes/improve-natural-voice-interaction/implementation-status.md)。Hinter显示的“语音结束至首音发送”使用服务端同一monotonic时钟，包含真实判停等待；这是收到人声后的服务端发送口径，未把它等同设备实际可听延迟。云ASR/RTC声学聚焦仍为条件性P1，不会借文本模型凭证上传原声。

本次自动回答、异步Hint、短句流式语音和即时回应实施见[实施记录](../openspec/response-flow-implementation.md)。豆包云端原生双向TTS仍是可选增强，未在本轮启用。


### 单输入汇总答复

公开时间线按原始 Talker message_id 汇总，稳定答复 ID 为 `reply-<message_id>`。每个后台子问题仍独立执行工具、隐私与人工确认策略，但附和、内部失败、重试和补充 attempt 不再生成独立公开气泡。首次等全部分支文字结果可用后显示，分项结构整理不阻塞正文显示；未知状态也是有效结果，不会等待人工无限挂起。

`answer_parts` 由主模型从已验证公开答案中整理，已知项必须是原答案的连续引用，不能新增事实。子项有稳定 ID 和 known/partial/unknown/clarify/refused/withdrawn 状态。后续补充优先替换同项，未涉及的已知项保留；显式撤回或纠正可清除旧值。新版准备期间保留完整旧版，按问题版本和最新 attempt ID 防止晚到覆盖。

Hinter 可通过 `POST /sessions/{session_id}/answers/{card_id}/parts/{part_id}` 提交指定项的提示。服务端验证角色、卡片归属、子项及 expected_answer，提示仍通过原有规则生效与回答检查。“仅后续应用”与此接口无关，不修改旧卡片。汇总卡片的撤回会撤回所关联的全部原始 attempt。

实时 PCM 继续使用底层 attempt response_id 和原音频协议；唯一气泡的复制与重播覆盖当前汇总。多个片段或保留旧已知项时使用整份汇总文字的浏览器语音，避免只播放最后一次纠正片段。已验证并汇总的最新版才进入 Wiki 整理，未知和过时 attempt 不作为新事实写入。

文字与播报完成分别处理：`text_complete` 只在有效正文生成完毕后置为真；`text_done` 是传输结束信号，取消时也可能为真，不能单独作为完整正文依据。汇总气泡在全部分支文字结果可用时显示，独立于 `audio_done` 和后台分项整理；已完成正文在音频被打断后继续可见。历史记录仅在 `model_done_ms` 存在时把中断回答视为完整正文。

公开问题的 Wiki 证据为 partial/provided 时，路由继续执行 web_search 补全缺失公开项；检索词只能来自公开原问题，不能包含 Wiki/Hint 的私有事实。回答合并已提供内容与联网结果，分别标明来源；工具返回不等于全部指标已核实，搜索失败也保留已有事实。完整匹配的授权事实可直接回答；禁令、内部数据和明确人工确认规则保持优先。

单问题与多问题使用不同的呈现/播报路径：单问题直接保留全部已验证原文并分段同步显示，不调用分项整理模型。多问题先完成分项整理并发布原气泡，再根据同一份项目状态生成语音；后续纠正以自然的更新提示开头，只读变化项。播放/历史记录保存实际 spoken text，整份重播始终对应当前完整气泡。某一整理行引用失败只保留该项旧值，其他合法更新仍写入；句子索引回退只能选择已验证原文。

输入理解以完整用户意图为先：正常间接问句不按 what/how 从句拆碎，句尾 is/are 不判定为内容未完成。ASR 冲突是诊断，所有有效输入仍由主模型路由；主模型可确认专名拼写/语法已消歧，真正的金额、标识符、否定、单位和日期冲突继续要求具体澄清。禁止使用第一个原始歧义片段拼接意义追问，尤其不能追问正常的请求前缀。
