# 输入预处理层

入口位于 `backend/app/employee/input_preprocessing/`，在聊天记录、气泡和 Agent Run 创建之前执行。

## 流程与模块

1. `rules.py`：空白、纯尾音、重复字符和明确的孤立引导语直接过滤；保留明确的否定、停止指令和数字。`voice_text.py` 仅保留断句排版及兼容导出。
2. `language.py`：根据当前请求识别主语言。中英混合输入交给分类器确认：中文句式中的英文名称、术语使用中文；英文句式中的一两个中文词使用英文。
3. `classifier.py`：对短语音做一次无工具的 JSON 分类，同时判断语言。不生成回答，不补写未说完的句子，不访问 Wiki、私有 Hint 或联网工具。
4. `pipeline.py`：统一编排阶段并返回 `InputDecision`（有效性、回答语言、原因、置信度、判断来源、版本及是否可重试）。未来的输入策略在这里增加阶段。
5. `repository.submit_input`：先鉴权、读取幂等结果及最多四条可见对话，释放数据库连接后预处理，再重新鉴权并锁定线程提交。分类网络请求不持有数据库锁。

当前短语音范围：含中日韩字符时不超过 24 个字符，否则不超过 12 个词或 80 个有效字符。长度只是决定是否需要进一步判断，不是拒绝条件。`I means.` 等孤立引导语由规则过滤；`I miss.` 由语义阶段判为残句；`I miss you`、简短提问、有上下文的名称回答都可以接受。普通手输文字和明确修订视为用户主动输入，不按 ASR 噪声过滤。

分类器仅接收当前文本和最多四条同线程、公开、未撤回的用户/助手对话，每条最多 500 字符。历史内容只帮助判断简短回答是否有意义，不能用历史话题补齐残句，也不决定本轮语言。分类结果必须符合字段白名单，语音必须判定 valid 且置信度至少 0.8 才能进入后续流程。

## 提交与交互

- 无效输入返回 `ignored=true`，不写 conversation record、问题投影或 Run，不产生用户/AI 气泡，也不播快速回应。
- 分类失败、超时或返回无效 JSON 时，待判断的短语音不被放行；返回可重试状态。通话内只显示重试提示，语音输入草稿仍保留，可重试或编辑为文字发送。暂时失败不缓存为已完成的幂等结果。
- 云端 ASR 接收与按序输入确认分离，确认队列最多八条；队列满时给通话内提示，不创建占位聊天气泡。录音转文字的中间结果继续只是可编辑草稿，提交时才经过预处理。
- 待语义判断的短片段不会作为 partial activity 打断播放；确认有效的正式输入可以打断。明确停止指令保留快速路径。
- 判断结果保存在用户记录的 `metadata.input_preprocessing` 中，绑定来源修订。正式回答和缓存短回应使用同一语言。旧记录、修订内容通过同一语言阶段处理；Hinter 续答使用原始用户请求的语言。
- 中文请求里夹英文产品名使用中文；英文请求里夹一两个中文词使用英文。显式的翻译或指定输出语言请求优先。Wiki、Hint、旧回答的语言不能改变本次语言选择。

## 配置

默认复用当前 Agent 模型。可独立设置 `INPUT_PREPROCESS_PROVIDER`、`INPUT_PREPROCESS_MODEL`、`INPUT_PREPROCESS_BASE_URL`、`INPUT_PREPROCESS_API_KEY` 接入更快的兼容模型。默认超时 `INPUT_PREPROCESS_TIMEOUT_SECONDS=6`（限制 2–12 秒），不自动重试；输出最多 160 tokens，关闭已有 DeepSeek 配置的思考模式。配置值和凭据只在服务端使用。

不回写或删除历史会话。语言策略交给 Agent 提示执行，语义判断仍可能有误判；当前版本以不产生无意义气泡为优先，保留有效短输入的规则与上下文判断。
